# Retryable writes and jobs

Read before changing mutations, retries, transactions or asynchronous side effects. Define transaction scope, external effects, idempotency key scope, conflict behavior and durable deduplication. Recover explicitly from partial database/message failure; use an outbox only for a demonstrated need. Retry classified transient failures within a deadline only when repeated effects are safe. Propagate cancellation. Background jobs need observable outcomes and bounded retries. OpenAPI is appropriate only for supported HTTP contracts; preserve the target dialect and design-first/code-first practice. Exercise duplicates, failure after commit, timeout and existing-client compatibility. Configuration/deployment dependencies are recorded, not activated implicitly.
