# Custom interaction checks

Read only for custom widgets, keyboard/focus defects or changed announcements. Consult the exact W3C APG pattern, not the whole site. For a modal: named dialog, appropriate initial focus, contained Tab/Shift+Tab, Escape/close action, inert background and sensible returned focus. Do not claim modality by adding aria-modal alone. Prefer native semantics and inspect existing implementation before replacement. Exercise long content, narrow/wide layouts, reduced motion and slow/error responses. Automated accessibility checks supplement keyboard and assistive-technology assessment; record manual checks omitted. Keep private keys out of browser bundles. Measure rendering/loading before adding caches or memoization. [W3C pattern](https://www.w3.org/WAI/ARIA/apg/patterns/dialog-modal/) re-read 2026-10-07; re-check current behavior at use time.

For form notifications, associate the message with its control, explain correction, and expose dynamic feedback to assistive technology without duplicate announcements or gratuitous focus stealing. Submission error summaries should identify affected controls and permit reaching them. Read only the relevant [W3C notifications section](https://www.w3.org/WAI/tutorials/forms/notifications/) for the changed behavior (read 2026-10-07).
