# Conditional route map

Read only when target/output evidence does not identify a direct specialist. Explicit user skill/tool and inspected target win over keywords.

- User needs/task flow: product-ux-design; mobile flows: mobile-product-design.
- Appearance/tokens: visual-design-system. Agreed browser UI implementation: web-frontend.
- Editable vector/SVG: graphics-assets. Raster generation/edit: installed imagegen directly.
- Server: backend-api; durable schema/query: database-engineering; Android Room: android-data-and-sync.
- Auth/privacy: application-security; imported content/dependency/CI trust: supply-chain-security.
- Ownership/topology: system-architecture; Android boundaries: android-architecture.
- Regression design: engineering-testing; service diagnosis: reliability-observability.
- Known Android task: direct Android specialist. Unfamiliar Android: android-router.
- Web UI/API/storage feature: fullstack-delivery; select stages, never stack coordinators.
- Word/PDF/slides/sheets: installed artifact specialist; do not load engineering guidance.
- iOS/Flutter/React Native, desktop, pipelines, games or ML: inspect actual target and use current primary docs when no dedicated skill exists. Do not route React Native to web just because React appears.
- Unrelated requests: no engineering skill.

If the output itself is ambiguous, inspect available evidence first; ask a bounded question only when the answer changes the work. No unrequested imports, framework migration, monitoring or fan-out. A reference is opened for a named decision, not every task; earlier content remains until host compaction.
