# Storage evolution and recovery

Read before schema changes, backfills or backup/restore work. Define compatibility for old/new clients; use expansion/backfill/contraction where needed. Assess locks/runtime on representative isolated data. Define resumability, failure recovery and roll-forward/rollback; dropping a field is not a generic rollback. Model retention and deletion explicitly. Evaluate engine-specific isolation/deadlocks and retry entire transactions only when effects are safe. Define recovery point/time objectives, access and retention. Restore backups into an isolated environment; backup success alone does not prove recoverability. Record unperformed restore tests and actual lock/runtime evidence. Never infer permission to inspect live records or run executing query-plan commands.
