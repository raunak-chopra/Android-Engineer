## When to use

## When not to use

Mobile-specific flows: mobile-product-design. Agreed appearance: visual-design-system. Code: target specialist.

## Workflow

1. Inspect the product brief, users, constraints and existing evidence.
2. Separate observed needs from hypotheses; name the primary task.
3. Model entry/exit, alternatives and failure states; avoid deceptive defaults.
4. For research/usability work read [research](references/research.md).
5. Hand off a task flow, content hierarchy, assumptions and acceptance evidence.

## Acceptance criteria

- No invented user findings; implementation only when requested.
- Preserve target conventions and permission boundaries.
- Record checks/omissions; get fresh-context review for Tier 2 changes (AGENTS.md).
