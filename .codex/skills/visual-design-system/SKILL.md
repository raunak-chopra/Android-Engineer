## When to use

Use for the stated scope.

## When not to use

User needs/flows: product-ux-design. Code-only styling to an approved spec: web-frontend. Assets: graphics-assets.

## Workflow

1. Inspect existing tokens/components, brand constraints and target platform.
2. Choose an original direction that serves content; preserve approved choices.
3. Define semantic tokens and component states; avoid forced aesthetic defaults.
4. For reusable systems/adaptive states read [handoff](references/handoff.md).
5. Verify contrast, zoom/long content and state clarity; hand off implementable specs.

## Acceptance criteria

- A mockup is a design artifact, not working UI or a tested user flow.
- Preserve target conventions and permission boundaries.
- Record checks/omissions; get fresh-context review for Tier 2 changes (AGENTS.md).
