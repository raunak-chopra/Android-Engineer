# Visual system handoff
Read for a reusable design system or responsive component specification. Reuse existing semantic tokens before adding aliases. For a new system, consider three layers: primitives, semantic roles (`bg/fg/border` across `default/subtle/muted/emphasized/status` plus contrast-paired `on-*` roles), and component/slot recipes. Treat visual `variant`, `density` (`comfortable`/`compact`) and tactile modifiers (`radius`, `depth`) as orthogonal axes. Define typography hierarchy, spacing, color roles, surfaces and `default/hover/focus-visible/pressed/loading/disabled/error/selected` states. Use `tabular-nums` where stable numeric alignment helps. Guard hover-only effects with `@media (hover: hover)`. For reduced motion, reduce nonessential movement and stop redundant decorative loops when using static fallbacks; retain necessary rendering. Include responsive behavior, long/localized content, contrast and zoom choices. Specify component behavior without confusing it with rendered appearance. Name asset references, sizes and export requirements; consult the [local resource library](../../../../docs/RESOURCE_LIBRARY.md) before recreating common icons or effects, and never copy another brand's identity or restricted assets without rights review. Validate representative small/large layouts and affected states. Do not require Storybook or a component framework if the target does not use it; any new tool requires its approval. [USWDS tokens](https://designsystem.digital.gov/design-tokens/), [GOV.UK styles](https://design-system.service.gov.uk/styles/) (read 2026-10-07) and [design deep dive](../../../../docs/research/design-resources-deep-dive-2026-10-21.md) (2026-10-21); adapt principles, not their brand.
