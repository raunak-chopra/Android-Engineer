# Visual direction and HUD critique

Read for visual design or HUD critique. Original synthesis, 2026-10-12. Apply to the selected genre and preserve existing direction.

Define the player promise, camera, verbs, session context and production limits. Preserve selected ideas separately from alternatives so later agents do not replace the design. Build a slice with a learning action, round, failure/retry and pause/resume. Whitebox rules and a representative art pass answer different questions.

Use a few relevant references or existing screens; explain transferable decisions in silhouette, value contrast, material, typography, palette and motion. References do not permit copying proprietary art. Compare materially different options only when direction is unresolved.

Map each visible element to a player decision and urgency. Action games need immediate recognition and a clear aim/camera region; strategy/card interfaces may be the play space. Do not impose one density percentage or minimalism across genres. Reveal occasional detail in menus while keeping needed action information visible. Apply consistent warning, resource, selection and icon meanings.

Inspect separation against busy gameplay, not only a quiet mockup. Use backing, shape and placement to maintain legibility. Frames, textures and animation should reinforce the setting; effects cannot compensate for ambiguous actions.

For every critique identify observed problem, player consequence, correction and a check that could disprove it. Fix unreadable critical information and task blockers before decoration. Screenshots assess composition; a playable build assesses input and feel.

For asset/screen handoff read [contracts](assets-and-screen-contracts.md); for runtime/usability verification read [evidence](playtest-evidence.md).
